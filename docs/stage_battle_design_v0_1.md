## 1. 目的と方針の変更
- 目的: 国や州ごとの特性（`profile.json`）を、実際に遊べるステージとバトルにする。ドイツ・米国・（将来）日本で、同じバトルの核を使い、違いはデータだけで出す。
- **方針の変更**: これまで「タワーディフェンス（TD）の処理はコアに置かない」としていた（`decision_log.md`）。これを、**「画面を持たない純粋な計算だけ」はコアに置く**に変える。描画・効果音・広告・課金・素材は、従来どおり各アプリ。
- 理由: (1) 国ごとの違いを1か所で実装できる。(2) 画面なしで、数千回の自動対戦によるバランス確認ができる。(3) `profile.json` を読む側が、まだどこにもない。

## 2. 範囲
| コアに入れる（`lib/battle/`、`dart:ui`・Flutter に依存しない） | 各アプリに残す |
|---|---|
| ステージ生成（進路・設置枠・ウェーブ） | 画面・アニメ・効果音・演出 |
| バトル計算（敵の移動・施設の攻撃・敵の能力と行動・経済・勝敗） | 素材（`skin` id から絵を引く） |
| 国の目玉（`signature`）・天候（`weatherEvent`）の効果計算 | 広告・課金・ランキング・実績 |
| イベント出力（UI・効果音が購読する） | 操作（タップで施設を置く）・チュートリアル |
| 自動対戦（バランス確認用のボット） | 難易度の名前・文言 |

## 3. 既存の実装との関係（調査結果）
日本の「地理パズル王」には、すでに独自の `TdEngine`（約1500行・静的メソッド）がある。
- 盤面は **8×8 のグリッド**、進路は `GridPos` の列、施設は6種＋都道府県限定施設、敵は4種（normal/speedy/armored/healer）＋ボス
- 状態は不変の `TdGameState`、`tick` で進める。フェーズは `prep/wave/waveEnd/victory/defeat`
- ウェーブは `WaveDefinition`（敵数・基礎HP・出現間隔・ボス有無・敵の種類）。基礎HPは `48×波番号`（都道府県）、`70×波番号`（地域戦）など。乱数は `Random()`（再現できない）

**方針**: コアの新エンジンは、**用語・データの形・計算の流れを既存に合わせる**（将来の移行を楽にする）。ただし、(1) 乱数は決定的な `Rng`、(2) 状態と計算を分離して画面なしで動かす、(3) 国ごとの特性は `profile.json` から受け取る、の3点は新規。**日本側は当面触らない**。コアのバトルがドイツで安定し、日本の挙動と比較できるようになってから、移行を決める。

## 4. データの形
### ステージ（`Stage`）
| 項目 | 内容 |
|---|---|
| id | 地域id（例 `DE-BY`）＋難易度 |
| grid | 列数・行数。**州ごとに違う**（§5.1の規則。`profile.regions[id].grid` で上書き可） |
| path | 進路（`GridPos` の列。開始辺→拠点） |
| slots | 施設を置ける枠（進路に隣接するマスなど。進路上には置けない） |
| waves | `WaveDefinition` の列（敵数・基礎HP・出現間隔・敵の構成・ボス） |
| base | 拠点HP |
| economy | 開始コイン・収入・施設の値段（`profile.economy` の倍率適用後） |
| trait | 地域の特性（`RegionTrait`: terrain / facilityBonus / weatherEvent / backdrop / exclusiveFacility / enemyBias） |
| season | 季節（spring / summer / autumn / winter。§6.5） |
| kind | 種別（通常／地方決戦／エクストラ。§6.9） |
| difficulty | easy / normal / hard（§6.8） |
| seed | `fnv1a('<packId>|<regionId>|<difficulty>')`。同じ入力は同じステージ |

### バトルの状態（`BattleState`）
既存の `TdGameState` に対応: 施設（位置・種類・レベル）、敵（位置＝進路上の進み具合・HP・状態異常・能力）、コイン、拠点HP、現在のウェーブ、フェーズ、残り時間、天候の効果、スコア。**不変**（`copyWith`）か、内部で可変にして外へは読み取り専用で出すかは未決（§11）。

### 4.2 データの追加（パック側。ステージ生成の前提）
地図の形を盤面にするため、`regions.json` に次を足す（`tools/` の変換スクリプトで生成し、検証で守る）。
| 項目 | 内容 | 検証 |
|---|---|---|
| `capitalPos` | 州都の位置 `{x, y}`（`geo.geojson` と同じ座標系。ドイツは経緯度、米国は焼き込み済みの平面） | **その州の形の中にある**（外なら不合格）。座標の根拠（緯度・経度）はスクリプトの表に残す |
| `neighbors` | 隣り合う地域の id の列。ポリゴンの共有する境界から**自動で求める**（手書きしない） | 対称（AがBの隣ならBもAの隣）、実在する id |
| `coast` | 海・国境に面する境界の有無（隣の州と接していない境界がある） | 任意 |

- 隣り合う地域がない（島・飛び地。例: US-HI、US-AK の一部）は、入口を「海から」にする。
- 州都の座標は一般に知られた位置（市の中心）。出典は、パックの出典欄に追記する（地名・位置は公共の事実）。

## 5. ステージ生成
入力: `RegionPack`（地域）、`CountryProfile`、難易度、seed。出力: `Stage`。

### 5.1 グリッドの大きさ（州ごと）と、州の形による切り抜き
- 解像度の基準の一辺 = `pathLength` で決める（short=6 / medium=8 / long=10。仮）。
- 地域の外接矩形の縦横比 `a`（幅÷高さ。投影後）を使い、`cols = round(基準 × √a)`、`rows = round(基準 ÷ √a)` とし、4〜12 に収める。横長の州は横長の盤面になる。
- **州の形で切り抜く**: 各マスの中心が、その地域のポリゴンの内側にあるマスを「陸地マス」にする（外側は使えない）。飛び地・島は、最大の連結成分だけを使う（残りは飾り）。
- **陸地マスが少なすぎる州**（都市州。例: DE-HB・DE-HH・DE-BE、US-DC・US-RI）は、解像度を上げる（陸地マス 36 以上になるまで一辺を増やし、上限 12）。それでも足りなければ、上限まで上げて、そのまま使う。
- `profile.regions[id].grid`（`{cols, rows}`）があれば、それを優先（手で調整する用）。範囲は 4〜12。
- 画面は盤面の大きさに合わせて拡縮する（アプリ側）。設置枠の数・敵の数・進路の長さは、陸地マスの数に比例して調整する。

1. **進路**: 陸地マスの上に、入口（§5.2）→拠点（州都のマス）まで、自分自身と交差しない経路を seed つきの探索で作る。長さは `profile.pathLength` で決める（short / medium / long。陸地マスに対する割合の目安は仮: 25〜35% / 35〜45% / 45〜55%）。地域ごとに形がばらつくよう、seed に地域idを混ぜる。作れなければ、解像度を上げて作り直す（上限まで）。
2. **設置枠**: 進路に隣接するマスを枠にする。枠数は進路の長さに比例（仮）。限定施設（`exclusiveFacility`）は、その地域だけ置ける。
3. **ウェーブ**: 波数は既定5（地域戦は7）。各波の敵の構成は `enemyMix` × 地域の `enemyBias` を重みにして、決定的に決める。敵の基礎HPは既存の式（`48×波番号` ほか）を既定とし、`enemies` の倍率を掛ける。最終波にボス（既存の4種のボススキル）。
4. **地形**: 地域の `terrain`（sea / mountain / urban / agriculture / mixed）を、既存の地形補正（施設の種類ごとのボーナス）に渡す。`facilityBonus` を掛ける。
5. **背景・見た目**: `backdrop` の id をそのまま出力に含める（描画は各アプリ）。

### 5.2 拠点・入口・隣の州（地図とのつながり）
- **拠点 = 州都**: `capitalPos` に最も近い陸地マスを拠点にする。画面には州都の名前を出す（ドイツ語・英語など、`strings` の `capitals`）。
- **入口 = 隣の州**: 入口は、`neighbors` の境界（その隣の州と接している縁）にある陸地マスから選ぶ。どの隣から来るかは seed と波で決める。入口には**隣の州の名前**を出す。
- **敵の出身**: 敵の構成には、入口の隣の州の `enemyBias` を混ぜる（例: 港の州から来る波は装甲型が増える）。隣の州の `terrain`・背景の色味も、敵の見た目の演出に使う（アプリ側）。
- **複数の入口**: 後半の波・hard・エクストラでは、入口が2〜3か所に増える（隣の州を複数覚える動機になる）。入口が1つしかない州（隣が1つ以下）は、増やさない。
- **海・川の州**: 隣のない縁（`coast`）は海からの入口にできる。海岸のマス（隣と接しない縁に面する陸地マス）では、漁業・港系の施設の威力が上がる（仮）。
- 地方決戦の盤面は、その地方の州の形を合わせた形（和）にする。拠点・入口の決め方は §10。

検証（テスト）: 進路が交差しない／進路と設置枠がすべて陸地マス／枠が進路上にない／**拠点が州都の位置に最も近い陸地マス**／**入口が隣の州の境界にある**／長さが範囲内／同じ seed で同じ結果／全地域（DE16・US51）でステージが作れる（作れない地域が出たら、解像度の規則を直す）。

## 6. バトル計算
### 6.0.1 進め方
- 固定時間刻み（例 1/30 秒）の `tick(state, dt)`。画面のフレームレートに依存しない。結果は `(state, events)`。
- イベント（敵の出現・撃破・拠点被害・施設の攻撃・天候の発生・勝敗）を返し、画面と効果音がそれを購読する。

### 6.0.2 敵（`profile.enemies` を適用）
- 移動: 進路上を `speed` で進む。`flying` は進路を無視して拠点へ直線。
- 体力・装甲: `hp` 倍率、`armor` を加算。`shield` は最初の一撃を軽減、`regen` は少しずつ回復。
- 拠点への被害: 到達時に `baseDamage` 倍率で拠点HPを減らす。
- `swarm`: 出現時に同時に複数。`disrupt`: 近くの施設の射程を縮める。
- 行動（`action`）: `heal_aura`（周囲の敵を回復）／`ranged_disable`（離れた施設を一時停止）／`sabotage`（施設の威力を一時的に下げる）。一定間隔で発動。

### 6.0.3 施設（`profile.attackActions` を適用）
- 撃ち方: `single`（単体）／`splash`（範囲）／`chain`（連鎖。跳ね返り数・減衰は仮）／`pierce`（貫通。装甲を一部無視）／`slow`（鈍足）／`burn`（継続ダメージ）。
- 威力・射程・間隔: 種類ごとの基礎値 × `attackActions` の倍率 × 地域 `facilityBonus` × レベル。
- 目標選び: 既定は「進路で拠点に最も近い敵」。

### 6.2 ハードでは敵が施設も攻撃する
- easy / normal: 施設は壊れない（従来どおり。`sabotage` `ranged_disable` による一時的な弱体化・停止だけ）。
- **hard**: 施設に耐久（HP）を持たせ、敵が施設を攻撃する。
  - 施設HP: 種類ごとの基礎値 × レベル（仮: 通常の施設は敵の基礎HPの約1.5倍。城・限定施設は多め）。
  - 敵の攻撃: 進路から射程（既定1マス。`ranged_disable` を持つ敵は長め）の施設を、`attack`（ウェーブの基礎攻撃力）× 種類の倍率で攻撃する。足速型は走り抜けるので攻撃しない、装甲型は重い一撃、ボスは範囲攻撃（仮）。攻撃中は進まず足止めされる（足止めが、施設の側の「守る」対価になる）。
  - 壊れた施設: 消える。コインを半分返す（仮）。**ウェーブの合間に、不足HPに応じたコインで修理できる**。
  - 施設の側の対策: 城は周囲の施設を守る（ダメージ軽減）、聖堂（神社の枠）は周囲の施設を回復する（仮。既存の「神社」の役割を確認して合わせる）。
- 既存の `profile.enemies.action`（`sabotage` / `ranged_disable`）は、全難易度で有効（施設を壊さず、一時的に弱める）。

### 6.3 バトルの進め方の補足（戦闘の順序）
1. 敵の出現 → 2. 敵の移動・足止め → 3. 敵の攻撃（hardのみ施設へ）→ 4. 施設の攻撃 → 5. 状態異常・継続ダメージ → 6. 撃破・コイン → 7. 拠点への到達 → 8. 勝敗判定。この順序を固定し、決定的にする。

### 6.4 天候イベント
- 地域の `weatherEvent` が、そのステージで**ウェーブ中に1〜2回**（難易度で増える）、決定的な時刻（seedから）に起きる。持続は数秒〜十数秒。起きる前に予告イベントを出す（アプリが画面で知らせる）。
- 効果（仮。§10-3 で調整）:

| 種類 | 射程 | 敵の速さ | 施設の威力・攻撃速度 | その他 |
|---|---|---|---|---|
| hurricane | −1マス | −15%（押し戻す） | −10% | 飛行の敵が出現しにくい |
| tornado | ±0 | +10% | ±0 | 設置枠のうち1か所が一時使用不可 |
| blizzard | −1マス | −25% | −15% | 継続ダメージ（burn）が弱まる |
| heatwave | +1マス | ±0 | 攻撃速度 −10% | 回復（regen）の敵が強まる |
| wildfire | ±0 | ±0 | ±0 | 進路沿い数マスに継続ダメージ（敵・施設とも）。hardは施設も燃える |
| flood | ±0 | −20% | ±0 | 低い枠（農業・漁業）の威力が +15% |
| earthquake | ±0 | ±0 | ±0 | 設置枠から1つの施設が数秒停止（`ranged_disable` と同じ扱い） |
| storm | −1マス | −10% | ±0 | 漁業・港系の施設の威力 +10% |

### 6.5 季節
- ステージごとに季節を1つ持つ（**エクストラは波ごとに季節が巡る**）。地域の既定は、`profile.regions[id].season`（任意）。省略時は、天候から推定（blizzard→winter、heatwave・wildfire→summer、hurricane・storm→autumn、tornado・flood→spring、天候なし→seed で決定）。
- 季節の効果（仮）:

| 季節 | 敵 | 施設・経済 | 天候との関係 | 背景（パレットを寄せる） |
|---|---|---|---|---|
| spring | 回復（regen）の敵が強い | 農業の威力 +10% | tornado・flood が起きやすい | 明るい緑 |
| summer | 足速型がやや速い（+5%） | 漁業の威力 +10%、攻撃速度 −5% | heatwave・wildfire が起きやすい | 濃い緑・青空 |
| autumn | 通常の敵が少し硬い（+5%） | 撃破コイン +10%（収穫） | hurricane・storm が起きやすい | 黄・橙 |
| winter | 全体に遅い（−10%） | 射程 −0（見え方のみ）、炭鉱・工業の威力 +10% | blizzard が起きやすい | 白・青灰 |

- 季節と合わない天候は起きる確率を下げる（例: summer に blizzard は起きない）。確率の表は §10-3 で決める。
- 見た目: 背景の配色を季節に寄せる（アプリ側。コアは季節の id と、背景の `palette` に掛ける調整の指示だけを返す）。

### 6.6 限定施設
- 地域の `exclusiveFacility` の施設は、その地域でだけ置ける（日本と同じ考え方）。1つのステージに1種。
- 効果は種類（原型）で決める（仮。ドイツ10種・米国9種を `profile` に書いた id に対して設計する）:

| 原型 | 効果 | 該当（id） |
|---|---|---|
| 強化の核（周囲の施設を強化） | 周囲1マスの施設の威力・攻撃速度 +15% | `automotive_works`・`aerospace_works`・`tech_campus`・`national_lab` |
| 港・交通（敵を遅らせる） | 進路の近くの敵を鈍足にする | `seaport`・`container_port`・`pipeline` |
| 資源（コインを生む） | 撃破コイン +X%、または一定間隔でコイン | `stock_exchange`（DE-HE・US-NY）・`oil_derrick`・`ruhr_works` |
| 醸造・工房（継続ダメージ・範囲） | 範囲に継続ダメージ | `brewery`・`distillery`・`winery`・`porcelain_works` |
| 象徴（拠点・守り） | 拠点HPの回復、または施設を守る | `parliament`・`capitol`・`wartburg` |
| 宇宙・先端（長射程） | 長射程・貫通 | `space_center` |

- 限定施設は、置ける数・値段・効果の具体値を、自動対戦（§8）で決める。**戦争や特定の歴史を連想させる意匠にしない**（施設の見た目は `profile.facilities` の `skin`）。

### 6.7 スキル（コアに入れる）
- 既存の「ウェーブごとのスキル選択」をコアに移す。ウェーブの合間に、決定的な乱数（seed とウェーブ番号）で候補を3つ出し、1つ選ぶ。効果は**次のウェーブのみ**（複利で積み上がらない）。
- 既存の4種を初期の一覧にする: `waveAtkBonus`（施設ダメージ +25%）、`waveRangeBonus`（射程 +1マス）、`waveCoinBonus`（撃破コイン +20%）、`waveAtkSpeedBonus`（攻撃速度 +15%）。
- 追加の候補（仮）: 修理（施設を一定量回復。hard向け）、鈍足、天候の無効化（次の天候を1回防ぐ）、季節の恩恵の強化。国ごとのスキル（`profile.skills`）は将来の拡張。
- コアは `skillChoices(state)` と `chooseSkill(state, id)` を提供し、名前・説明文の文言はアプリ側。ボスのスキル（`speedBurst` / `hpRegen` / `summon` / `stunFacility`）もコアで計算する。

### 6.9 エクストラステージ（クリア後）
地理パズル王の「地方決戦」（地域でまとめて戦う・7波・1.2倍）と「歴史ステージ」（全ステージをハードでクリア後に解放・8〜10波・1.4倍）にならう。

| 種別 | 解放条件（案） | 内容（案） |
|---|---|---|
| **地方決戦** | ある地方の州を一定数（例: 過半数）クリア | 地方（ドイツ=北・東・南・西、米国=北東部・南部・中西部・西部など。分け方は §10）の州の特性を混ぜる。7波、基礎HP 1.2倍、敵の構成は地方の特性、その地方の限定施設を複数置ける |

  1. 戦争・虐殺・差別・特定の政治体制や宗教の優劣を主題にしない。敵は人ではなく、幻想の存在にする。

  4. 舞台の地域・先住民の文化に配慮し、題材を決める前に、事実と配慮の点を調べて確認する（ゲーム内の説明文にする前に必ず）。

- ステージの数・題材・舞台・季節は、すべて仮。素材の制作（背景・ボス・敵の見た目）に入る前に確定する。
- エクストラは `Stage.kind` で区別し、生成の入力（地域の集合・波数・倍率・季節の巡り）を変えるだけで、同じ `StageGenerator`・`BattleEngine` で動く。

### 6.10 経済・勝敗
- 開始コイン・収入・施設の値段に `economy` の倍率。撃破でコイン。
- 拠点HPが0で敗北。全ウェーブを終えて勝利。

### 6.11 国の目玉（差し込み式）
`SignatureRule` の形で、`signature.id` ごとに実装を差し込む。バトルの計算は、目玉の有無を知らない。
- `federal_specialties`（ドイツ）: 州ごとの得意分野で施設を強化。隣り合う州の得意分野がそろうと追加ボーナス（隣接関係は地図から作る）。
- `weather_extremes`（米国）: 天候イベント（§6.4）と季節（§6.5）を強調する目玉。米国は地域ごとの `weatherEvent` が多く、発生回数・効果を大きくする（仮）。

### 6.12 知識が修理とスキルの燃料になる（クイズ連動）
- **スキル選択**: ウェーブの合間に小さなクイズを1問出す。**正解なら、候補3つから選べる**。不正解なら、候補から**1つがランダムに決まる**（何ももらえない、にはしない）。
- **ハードの修理**: 壊れた施設の修理に、クイズ1問を使える。正解で**無料**、不正解で**コインを払って修理**（不正解の罰はコインだけ）。
- **問題**: `QuizEngine` を使い、対象は**そのステージの州と隣の州**（州都当て・州名当て・「この州と接しているのは？」・形当て）。seed とウェーブ番号で決定的に出る。
- **オフにできる**: 設定で「クイズ連動オフ」にすると、スキルは3つから選べ、修理はコインだけになる（低学年・クイズが苦手な人・アクセシビリティ向け）。オフでも、クリアはできる。
- 計算はコアが持つ（`assistQuestion(state)` が問題を返し、`resolveAssist(state, correct)` が結果を返す）。表示はアプリ。
- 狙い: 「覚える→強くなる」を、バトルの流れの中に入れる。日本の既存の「問題は後で答える」と同じ発想。

### 6.13 デイリーのバトルとリプレイ（M5 以降）
- **リプレイ**: ステージ（packId・地域・難易度・seed）と、操作の記録（ティックと操作の列。施設の設置・アップグレード・撤去・スキル・クイズの正誤）だけを保存する。計算が決定的なので、同じ記録から同じ結果を再現できる（サーバーなしで検証できる）。
- **デイリーのバトル**: 日付（UTC）と packId から、ステージ（地域と難易度）を決定的に決める。全員が同じ条件で遊ぶ。結果は、既存のデイリーのように、**波ごとの 🟩🟥** で共有する（拠点HPの残りも添える）。
- **挑戦リンク**: 「私の配置に勝てる？」として、リプレイを共有できる（ゴースト表示は将来）。
- 検証: 同じ記録を再生して、保存された結果と一致すること（テスト）。ランキングに使う場合は、再生による検証が必要。

## 7. API の形（案）
```dart
final stage = StageGenerator(pack, profile).generate(regionId: 'DE-BY', difficulty: Difficulty.normal);
var s = BattleEngine(stage, profile).start();
s = engine.place(s, FacilityType.factory, GridPos(3, 2));   // 置けなければ null
final r = engine.tick(s, dt);                               // (state, events)
final q = engine.assistQuestion(s);                         // ウェーブの合間のクイズ（§6.12）
s = engine.resolveAssist(s, correct: true);                 // 正解ならスキル3択・修理無料
final replay = engine.toReplay(s);                          // 操作の記録（§6.13）
```
`QuizEngine` と同じく、乱数は `Rng(seed)`。`dart:math` の `Random` は使わない。

## 8. テストとバランス確認
- 単体テスト: ステージ生成（§5の検証）、敵の移動、各撃ち方、各能力と行動、経済、勝敗、同じ入力で同じ結果。
- **自動対戦**（`tools/` または `test/` の重いテスト。CIには入れず手動）: ボット（例: 進路に近い枠から順に、安い施設を置く／種類を偏らせる）が、全地域×難易度を多数回（seed を変えて）遊び、勝率・敗北した波・平均の拠点HPを出す。見る点:
  1. ドイツと米国で、同じ強さの施設を置くと有利不利がどれだけ出るか
  2. 特定の地域（例: 港の州）だけ極端に簡単／難しくないか
  3. 敵の能力・行動が、実際に勝率に効いているか（効かない設定は削る）
- 数値（基礎HP、倍率、ボーナス）は仮。この結果を見て調整する。

### M1 で実装して分かったこと（2026-10-17）
- 盤面にするのは**本土1つ**（州都を含むポリゴン。なければ最大）。小さな島・離れた土地は飾り（ハワイは州都のあるオアフ島）。ミシガン州は下半島だけ（上半島は海峡で切れるため盤面に入らない）。**上半島側の隣（ミネソタ・ウィスコンシン）からの入口は、現状は作れない**。必要なら、離れた土地を「連絡船」でつなぐ仕組みを足す（未決）。
- 隣の州が複数あるとき、入口は境界の長い隣ほど選ばれやすい。hard では最大3か所、波の後半で入口が増える。隣のない州（AK・HI）は海から。
- 進路の長さは、陸地マスに対する割合の目標（短 25〜35% ／中 35〜45% ／長 45〜55%）。目標を満たせないときは短くして、最後は最短経路。
- 設置枠は、進路に隣接する陸地マス（8近傍）。少なければ、進路に近いマスから足す（最低6）。
- 解像度は、陸地マスが36に届くまで上げる（上限12）。全州（ドイツ16・米国51）×3難易度で生成できることをテストで確認。一覧画像は `docs/concepts/stages_*.png`（`tools/make_stage_sheet.py`）。

### M2 で実装して分かったこと（2026-10-17）
- `BattleEngine`（`lib/battle/battle_engine.dart`）: 状態は**不変**（`copyWith`）。乱数を使わない（クリティカルは M3 で、決定的な `Rng` で入れる）ので、同じステージ・同じ操作は同じ結果。固定の刻み 1/30 秒（`advance`・`runToEnd`）。順序は §6.3（出現→移動→施設の攻撃→撃破→拠点への到達→勝敗）。
- 入っているもの: 敵の移動（進路上の位置）、施設の攻撃（`single`・`splash`。ほかの撃ち方は M3 まで単体として扱う）、装甲（ダメージから固定値を引く。最低1）、撃破の報酬（`12+3×波`、ボスは `60+5×波`。難易度と国の収入の倍率）、拠点への到達（既存の規則: easyは常に1、ボス・装甲は重い。国の `baseDamage` 倍率）、国の特性（敵の `hp`/`speed`/`armor`/`baseDamage`、施設の `attackActions` の威力・射程・間隔、地域の `facilityBonus`、経済の3倍率）、イベント出力、準備時間の自動の波開始。
- 入っていないもの（M3 以降）: 敵の能力（shield・regen・swarm・flying・disrupt）と行動、ほかの撃ち方（chain・pierce・slow・burn）、アップグレード・撤去、クリティカル、ボスのスキル、スキル選択、クイズ連動、天候・季節・限定施設、ハードの施設への攻撃。
- **バランスは未調整**: 開始のコインだけで施設を置き、あとは何もしない配置では、ノーマルでも3波目に敗北する（防衛なしは全州で敗北、十分な防衛＝城14基は勝利）。収入で買い足す自動対戦（M4）で調整する。

### アイデアの置き場（採用していない候補）
- 日付と連動する期間限定ステージ（米国のハリケーンシーズン 6〜11月、ドイツの秋の祭りなど）。端末の日付だけで出せる。
- 習得した州の施設が少し強くなる（クイズの習得とバトルをつなぐ。小さな補正に留める）。

## 12. リスク
- **範囲が大きい**: 既存の `TdEngine` は約1500行。M2の小さい範囲で、設計の誤りを早く見つける。
- **二重実装**: 日本の `TdEngine` とコアが並ぶ期間がある。移行までは、日本側を変えず、コアは日本の用語に寄せる。
- **バランス**: 国ごとの倍率が重なると、勝率が極端になりやすい。M4の自動対戦で見る。
- **州の形の切り抜き**: 細長い・島が多い州（US-HI・US-AK・US-MI・US-FL・DE-SH など）で、進路が作れない・陸地マスが足りない恐れ。最大の連結成分だけ使う、解像度を上げる、作り直す、の順で対処し、M1の一覧画像と全州のテストで早く見つける。
- **州都の座標の誤り**: 67件を手で用意するため、誤りが入りやすい。「州の形の中にある」検証で外れ値を弾き、一覧画像で目視する。
- **クイズ連動のしんどさ**: 負けが続くと嫌になる。不正解でも何かは得られる設計にし、オフにできるようにする。
- **面白さは計算では分からない**: M5で実際に遊んで確かめる。


### M3a で実装したこと

敵の能力（shield・regen・swarm・flying・disrupt）と行動（heal_aura・ranged_disable・sabotage）、撃ち方（pierce・slow・burn・chain）、クリティカル（決定的ハッシュ・約15%・2倍）、アップグレード・撤去、ボスのスキル（speedBurst・hpRegen・summon・stunFacility、8秒間隔）。残り（M3b）: 難易度の細部、スキル選択、chain の挙動テスト。

### M3b で実装したこと

スキル選択: `skillChoices(state)`（準備中だけ。seed と波の番号から決まる3つ。`repair` は hard だけ）と `chooseSkill(state, id)`。種類は `waveAtkBonus`（威力+25%）・`waveRangeBonus`（射程+1）・`waveCoinBonus`（撃破コイン+20%）・`waveAtkSpeedBonus`（攻撃速度+15%）・`slow`（敵の速さ×0.8）・`weatherBlock`（無効化の残り回数+1。天候は M3.5）・`repair`（停止・妨害を直す。施設HPの回復は M3.5）。効果は次の波だけで、波が終わると外れる。難易度の細部（波数・開始コイン・拠点HP・敵のHPと速さ・到達の被害）と chain の挙動をテストで確認。

### M3.5a で実装したこと

`lib/battle/weather.dart`（`Weather`）と、エンジンへの組み込み。
- 天候の予定: 波ごとに seed から決まる。1回目は波の開始から 8〜13 秒後、持続 6〜12 秒、hard は 14 秒おきに 2 回。3 秒前に予告（`weatherWarning`）→ `weatherStart` → `weatherEnd`。季節に合わない天候は起きない（blizzard は夏なし、heatwave・wildfire は冬なし）。
- 効果: 射程・敵の速さ・威力・攻撃間隔・継続ダメージ・regen・種類別の威力。wildfire は 1 秒ごとに全ての敵へ基礎HPの3%。tornado・earthquake は施設を1つ停止（earthquake 3秒、tornado は天候の間）。`weatherBlock` のスキルは次の1回を防ぐ（`weatherBlocked`）。
- 季節: spring（regen×1.5・農業+10%）、summer（足速型+5%・漁業威力+10%/攻撃間隔−5%）、autumn（通常の敵HP+5%・撃破コイン+10%）、winter（敵−10%速・鉱業と工業+10%）。
- 未実装（M3.5b 以降）: hurricane の「飛行が出にくい」、wildfire の「進路沿いだけ」と「施設も燃える（hard）」、flood の「低い枠」の判定（今は農業・漁業の威力+15%）。限定施設、ハードの施設への攻撃・修理。

### M3.5b で実装したこと

- **hard の耐久と攻撃**: 施設HP = 1波の基礎HP×1.5×レベル（城×1.5、限定施設×2）。敵は射程1マス（`ranged_disable` は2マス）の施設に、基礎HP×12%×種類の倍率（装甲×2、治癒×0.5、ボス×1.5で半径1.5マスの範囲）で1.5秒ごとに攻撃し、その間は進まない。足速型は走り抜ける。城・象徴の周囲1.5マスは被害×0.7。神社は2秒ごとに周囲の施設を4%回復。壊れた施設は消えて、使ったコインの50%が戻る。wildfire は hard で施設も燃える（1秒ごと基礎HPの3%）。
- **修理**: `repairCostOf`（不足の割合×使ったコイン×0.5）と `repair`。修理スキルは全施設を満タンにして停止・妨害も直す。
- **限定施設**: `placeExclusive`（1ステージに1つ）。原型6種（`exclusive.dart`）: core（周囲+15%）・port（近くの敵×0.7）・resource（撃破コイン+15%）・brewery（範囲の敵に毎秒 基礎HPの6%）・symbol（拠点HPを10秒ごとに1回復、周囲を守る）・space（射程4.5の貫通）。強化は不可、撤去は可。
- 値は暫定。M4 の自動対戦で調整する。

### M3.6 で実装したこと

`BattleEngine(stage, profile:, pack:, quizAssist:)`。`pack` を渡し、`quizAssist`（既定オン）が真のときだけ有効（`assistEnabled`）。
- `assistQuestion(state, {forRepair})`: ステージの州と隣の州から1問（地図から州名・州都から州名・州名から州都・形当て）。seed・波・用途・位置で決定的。
- スキル選択: `resolveSkillQuiz(state, correct:)`。正解→`skillUnlocked`（3つから `chooseSkill` で選べる）、不正解→3つのうち1つが自動で決まる。有効時はクイズ前の `chooseSkill` は null。オフなら従来どおり3つから選べる。
- 修理: `repairByQuiz(state, pos, correct:)`。正解は無料、不正解（またはオフ）はコインで修理。
- 制限時間: `assistTimeLimit`（hard は10秒、ほかは無制限）。時間切れは不正解として扱う（時間の計測は画面側）。
- 未実装: 「この州と接しているのは？」の問題（問題の種類の追加は M5 の画面と合わせる）。

### M4 で実装したこと（自動対戦のボットと、最初のバランス調整）

`lib/battle/bot.dart`（`BattleBot`）: 決定的な自動対戦。設置枠を進路への近さで並べ、敵の構成に効く施設をコイン効率で選び、最初の4つを置いたらレベル1→2の強化を優先、限定施設・スキル（クイズの正解率つき）・修理も使う。強さは `casual` / `regular` / `expert`（クイズ正解率・反応の遅さ・使う金額）。`BALANCE=1 flutter test test/balance_report_test.dart` で勝率の表を出す。

初回の調整（ボットの勝率、全地域）:

| | easy | normal | hard |
|---|---|---|---|
| ドイツ regular / expert | 100% / 100% | 50% / 44% | 0% / 13% |
| 米国 regular / expert | 100% / 100% | 94% / 90% | 16% / 33% |

ボットで分かって直したこと:
- 敵の種類を**段階的に出す**（通常→足速型（2波）→治癒型（3波）→装甲型（4波））。序盤から装甲型が出ると、安い施設ではダメージが通らない。
- **進路の長さで敵の速さを補正**（25マス基準、0.6〜1.25倍）。短い州（ドイツ）は遅く、長い州は速く。
- 拠点に近すぎる入口（6マス未満）を外す（進路が数マスの入口があった）。
- `ranged_disable` の敵の攻撃射程を 2.0→1.3 に。施設の射程の外から殴り続けて決着しない場面があった。
- 施設への攻撃力 0.12→0.10、hard の敵HP 1.3→1.15・速さ 1.15→1.08・撃破コイン 0.9→1.0。
- ドイツの敵の構成（装甲型 40%→25%）と開始コイン（1.0→1.3）、米国の開始コイン（1.2→1.0）。

分かっていること・次の課題: ドイツのnormalは米国よりかなり難しい（短い州が多い）。ボットは実際のプレイヤーより単純（再配置や天候への対応をしない）。casual / regular / expert の差が小さく、ボットの腕前の差はまだ弱い。hard は米国33%・ドイツ13%（expert）。

### M5（コア側）で実装したこと

画面の部品をコアに置いて、ドイツ・米国のアプリで共有する（素材は使わず、色と図形だけの最小版）。
- `BattleSession`（`lib/battle_ui/battle_session.dart`）: 画面とエンジンの間の操作役。速度（1倍・2倍）、一時停止、選択マス、直近のイベント、設置・強化・撤去・修理（クイズ連動つき）・限定施設・波の開始・スキル選択。時間はフレームから `tick(秒)` で渡す。
- `BattleView`（`lib/battle_ui/battle_view.dart`）: 盤面（海・陸・進路・設置枠・入口・拠点・施設・敵・耐久バー・選択と射程）を描き、マスのタップを返す。季節で地面の色が変わる。
- アプリ側（M5 のもう半分）: HUD（波・拠点HP・コイン）、施設の選択欄、スキル選択のクイズ、結果の表示、文言。

### 多言語対応（M5 と同時）

- 画面の文言は `i18n/battle.<言語>.json`（キー→文言）。原本は英語。足りない言語・キーは英語で表示（`UiStrings`）。コアのパッケージに同梱し、ドイツ・米国・（のちに日本）のアプリで共有する。
- 翻訳は Google翻訳（ローカルのセッション）で行う前提。`tools/i18n_check.py` の `missing`（翻訳用に足りない文言を出す）→ 訳す → `merge`（`{name}` などの崩れを検査して取り込む）→ `check`。手順は `i18n/README.md`。
- 地域名・州都名は従来どおり `packs/<国>/strings/<言語>.json`（`pack.json` の `languages` に言語を足す）。

### M6 で実装したこと（国の目玉）

`lib/battle/signature.dart`（`SignatureRule`）。`profile.signature.id` ごとに実装を差し込み、エンジンは `engine.signature` の窓口（施設の種類ごとの威力の倍率、天候の回数の加算、天候の効果の強さ）だけを使う。知らない id は中立。
- `federal_specialties`（ドイツ）: 守る州とその隣の州のうち、同じ種類を得意とする（`facilityBonus` にある）州が多いほど、その種類の施設が強くなる。2州で +5%、3州で +10%、4州以上で +15%（上限）。隣接は pack から数える（`pack` を渡さないと中立）。
- `weather_extremes`（米国）: 1つの波に起きる天候が1回増え、効果の標準からの変化が25%大きくなる。
- 副作用: ドイツ normal の勝率が上がり（regular 50%→69%）、米国は少し下がった（94%→86%）。国の差が縮んだ。

最新のボットの勝率（regular / expert）: ドイツ easy 100%/100%・normal 69%/63%・hard 0%/13%、米国 easy 100%/100%・normal 86%/84%・hard 16%/33%。

### M7a で実装したこと（地方決戦）

- **地方のデータ**: `profile.json` の `groups`（id → `regions`・`center`・`name`）。ドイツ=北・東・西・南、米国=国勢調査局の4地方。州は重ならず、全州が入る。検査（Dart・Python）つき。
- **生成**: `StageGenerator.generate(<地方id>, difficulty, kind: StageKind.regional)`。盤面は、地方の各州の本土の形を合わせたもの（最大14マス）。拠点は `center` の州都、入口は地方の外の隣の州（2か所以上）。離れた土地（アラスカ・ハワイなど）は盤面から外れる（`Stage.memberIds` が盤面にある州）。
- **内容**: 7波（easy 6・hard 8）、敵のHP×1.2、開始コイン×1.6、撃破コイン×1.3。天候・季節・限定施設は中心の州のもの（限定施設は盤面にある州ぶんを複数置ける：`Stage.exclusiveFacilities`・`placeExclusive(id:)`）。施設の得意分野は盤面の州のうち最大、敵の偏りは州の偏りの幾何平均、クイズは盤面の州と隣の州から出る。
- ボットの勝率（8地方、regular）: easy 多数、normal 約半分以上、hard は expert が時に勝つ程度。
- 次: M7b（エクストラ: 国ごとに3つ、歴史・伝記・伝説の題材、季節が波ごとに巡る）と、アプリ側の解放・進捗（M7c）。

### M7b で実装したこと（エクストラ）

- **データ**: `profile.json` の `extras`（各国3つ）。`id`・`basis`（legend/biography/history）・`regions`・`center`・`seasons`（波ごとに巡る4季）・`weatherEvent`・`backdrop`・`bossSkill`・`waves`（8・9・10）・`title`/`summary`/`fact`/`bossName`（言語→文言。英語が必須）。`fact` は**事実と伝承の区別**の注記（設計書 §6.9 の決まり5）。検査（Dart・Python）つき。
- **ステージ**:
  - ドイツ: ローレライの岩（ライン川の伝説、RP・HE）、グリムの森（民話、BW・HE）、ニーベルンゲンの竜（英雄伝説、RP）。
  - 米国: ポール・バニヤンの森（法螺話、MN・WI・MI）、ライト兄弟の空（伝記、NC）、月をめざして（歴史・業績、メキシコ湾岸の5州 FL・AL・MS・LA・TX）。
  - 設計書の案からの変更: 米国 E1 は離れた州（ME）をやめ五大湖の3州、E3 はつながらない FL・TX をやめ、アポロ計画の拠点があるメキシコ湾岸の5州にした。
- **生成**: `generate(<エクストラid>, difficulty, kind: StageKind.extra)`。盤面は州の本土の形を合わせる。敵のHP×1.4、撃破コイン×1.3、開始コイン×1.6（地方決戦と同じ）、波は8〜10、**季節は波ごとに巡り**（`Stage.seasonAt(wave)`）、**天候が標準より1回多い**、ボスのスキルは指定（`Stage.bossSkill`）。
- **エンジン**: 季節の効果は波ごとに引く（`facilityStats(f, wave:)`・敵・撃破コイン・regen・天候の適合）。
- **バランス**（expert のボット、6ステージ）: easy 5勝・normal 2勝・hard 1勝。ボットで分かったこと: 天候が `storm`・`blizzard`（射程−1）のステージは normal でも勝てなかったので、エクストラの天候は洪水・竜巻・地震・熱波にした。
- **題材の決まり**（§6.9）は守っている: 戦争・差別なし、敵は幻想の存在、国旗・国章・実在の人物の顔なし。**公開前に、ゲーム内の説明文の事実関係を確認する**（`fact` の文面は仮）。
- 次: M7c（アプリ側: 解放の条件・進捗・画面）。ボスの見た目・素材は後で。

### M7c（コア側）で実装したこと

`lib/battle/battle_progress.dart`（`BattleProgress`）: バトルのクリア記録と解放。画面にも保存先にも依存せず、保存はアプリ側（`toJsonString` / `fromJsonString`）。
- 記録: `recordClear(kind, id, difficulty)`。鍵は `<種別>:<id>`。
- 地方決戦の解放: その地方の州の**過半数**をクリア（どの難易度でも。半分ちょうどは不可）。
- エクストラの解放: **全州を hard でクリア**。
- 画面の文言を追加: `stage.mode.*`・`stage.locked.*`・`stage.progress`・`stage.about`・`stage.fact`・`stage.basis.*` など（`i18n/battle.en.json`）。
- 方針: 地方決戦・エクストラは、無料でない州のクリアが要るので、実質的に「全州解放」（買い切り）の内容。

## 1. 目的と方針の変更
- 目的: 国や州ごとの特性（`profile.json`）を、実際に遊べるステージとバトルにする。ドイツ・米国・（将来）日本で、同じバトルの核を使い、違いはデータだけで出す。
- **方針の変更**: これまで「タワーディフェンス（TD）の処理はコアに置かない」としていた（`decision_log.md`）。これを、**「画面を持たない純粋な計算だけ」はコアに置く**に変える。描画・効果音・広告・課金・素材は、従来どおり各アプリ。
- 理由: (1) 国ごとの違いを1か所で実装できる。(2) 画面なしで、数千回の自動対戦によるバランス確認ができる。(3) `profile.json` を読む側が、まだどこにもない。

## 2. 範囲
| コアに入れる（`lib/battle/`、`dart:ui`・Flutter に依存しない） | 各アプリに残す |
|---|---|
| ステージ生成（進路・設置枠・ウェーブ） | 画面・アニメ・効果音・演出 |
| バトル計算（敵の移動・施設の攻撃・敵の能力と行動・経済・勝敗） | 素材（`skin` id から絵を引く） |
| 国の目玉（`signature`）・天候（`weatherEvent`）の効果計算 | 広告・課金・ランキング・実績 |
| イベント出力（UI・効果音が購読する） | 操作（タップで施設を置く）・チュートリアル |
| 自動対戦（バランス確認用のボット） | 難易度の名前・文言 |

## 3. 既存の実装との関係（調査結果）
日本の「地理パズル王」には、すでに独自の `TdEngine`（約1500行・静的メソッド）がある。
- 盤面は **8×8 のグリッド**、進路は `GridPos` の列、施設は6種＋都道府県限定施設、敵は4種（normal/speedy/armored/healer）＋ボス
- 状態は不変の `TdGameState`、`tick` で進める。フェーズは `prep/wave/waveEnd/victory/defeat`
- ウェーブは `WaveDefinition`（敵数・基礎HP・出現間隔・ボス有無・敵の種類）。基礎HPは `48×波番号`（都道府県）、`70×波番号`（地域戦）など。乱数は `Random()`（再現できない）

**方針**: コアの新エンジンは、**用語・データの形・計算の流れを既存に合わせる**（将来の移行を楽にする）。ただし、(1) 乱数は決定的な `Rng`、(2) 状態と計算を分離して画面なしで動かす、(3) 国ごとの特性は `profile.json` から受け取る、の3点は新規。**日本側は当面触らない**。コアのバトルがドイツで安定し、日本の挙動と比較できるようになってから、移行を決める。

## 4. データの形
### ステージ（`Stage`）
| 項目 | 内容 |
|---|---|
| id | 地域id（例 `DE-BY`）＋難易度 |
| grid | 列数・行数。**州ごとに違う**（§5.1の規則。`profile.regions[id].grid` で上書き可） |
| path | 進路（`GridPos` の列。開始辺→拠点） |
| slots | 施設を置ける枠（進路に隣接するマスなど。進路上には置けない） |
| waves | `WaveDefinition` の列（敵数・基礎HP・出現間隔・敵の構成・ボス） |
| base | 拠点HP |
| economy | 開始コイン・収入・施設の値段（`profile.economy` の倍率適用後） |
| trait | 地域の特性（`RegionTrait`: terrain / facilityBonus / weatherEvent / backdrop / exclusiveFacility / enemyBias） |
| season | 季節（spring / summer / autumn / winter。§6.5） |
| kind | 種別（通常／地方決戦／エクストラ。§6.9） |
| difficulty | easy / normal / hard（§6.8） |
| seed | `fnv1a('<packId>|<regionId>|<difficulty>')`。同じ入力は同じステージ |

### バトルの状態（`BattleState`）
既存の `TdGameState` に対応: 施設（位置・種類・レベル）、敵（位置＝進路上の進み具合・HP・状態異常・能力）、コイン、拠点HP、現在のウェーブ、フェーズ、残り時間、天候の効果、スコア。**不変**（`copyWith`）か、内部で可変にして外へは読み取り専用で出すかは未決（§11）。

## 5. ステージ生成
入力: `RegionPack`（地域）、`CountryProfile`、難易度、seed。出力: `Stage`。

### 5.1 グリッドの大きさ（州ごと）
- 基準の一辺 = `pathLength` で決める（short=6 / medium=8 / long=10。仮）。
- 地域の外接矩形の縦横比 `a`（幅÷高さ。投影後）を使い、`cols = round(基準 × √a)`、`rows = round(基準 ÷ √a)` とし、4〜12 に収める。横長の州は横長の盤面、縦長の州は縦長の盤面になる。
- 面積が極端に小さい地域（都市州。例: DE-HB・DE-HH・DE-BE、US-DC・US-RI）は、一辺を1段小さくする（6→5など。下限4）。
- `profile.regions[id].grid`（`{cols, rows}`）があれば、それを優先（手で調整する用）。範囲は 4〜12。
- 画面は盤面の大きさに合わせて拡縮する（アプリ側）。設置枠の数・敵の数・進路の長さは、盤面の面積に比例して調整する。


1. **進路**: グリッド上に、開始辺→拠点まで、自分自身と交差しない経路を seed つきの探索で作る。長さは `profile.pathLength` で決める（short / medium / long。マス数の目安は仮: 16〜22 / 24〜32 / 34〜44）。地域ごとに形がばらつくよう、seed に地域idを混ぜる。
2. **設置枠**: 進路に隣接するマスを枠にする。枠数は進路の長さに比例（仮）。限定施設（`exclusiveFacility`）は、その地域だけ置ける。
3. **ウェーブ**: 波数は既定5（地域戦は7）。各波の敵の構成は `enemyMix` × 地域の `enemyBias` を重みにして、決定的に決める。敵の基礎HPは既存の式（`48×波番号` ほか）を既定とし、`enemies` の倍率を掛ける。最終波にボス（既存の4種のボススキル）。
4. **地形**: 地域の `terrain`（sea / mountain / urban / agriculture / mixed）を、既存の地形補正（施設の種類ごとのボーナス）に渡す。`facilityBonus` を掛ける。
5. **背景・見た目**: `backdrop` の id をそのまま出力に含める（描画は各アプリ）。

検証（テスト）: 進路が交差しない／枠が進路上にない／長さが範囲内／同じ seed で同じ結果／全地域（DE16・US51）でステージが作れる。

## 6. バトル計算
### 6.0.1 進め方
- 固定時間刻み（例 1/30 秒）の `tick(state, dt)`。画面のフレームレートに依存しない。結果は `(state, events)`。
- イベント（敵の出現・撃破・拠点被害・施設の攻撃・天候の発生・勝敗）を返し、画面と効果音がそれを購読する。

### 6.0.2 敵（`profile.enemies` を適用）
- 移動: 進路上を `speed` で進む。`flying` は進路を無視して拠点へ直線。
- 体力・装甲: `hp` 倍率、`armor` を加算。`shield` は最初の一撃を軽減、`regen` は少しずつ回復。
- 拠点への被害: 到達時に `baseDamage` 倍率で拠点HPを減らす。
- `swarm`: 出現時に同時に複数。`disrupt`: 近くの施設の射程を縮める。
- 行動（`action`）: `heal_aura`（周囲の敵を回復）／`ranged_disable`（離れた施設を一時停止）／`sabotage`（施設の威力を一時的に下げる）。一定間隔で発動。

### 6.0.3 施設（`profile.attackActions` を適用）
- 撃ち方: `single`（単体）／`splash`（範囲）／`chain`（連鎖。跳ね返り数・減衰は仮）／`pierce`（貫通。装甲を一部無視）／`slow`（鈍足）／`burn`（継続ダメージ）。
- 威力・射程・間隔: 種類ごとの基礎値 × `attackActions` の倍率 × 地域 `facilityBonus` × レベル。
- 目標選び: 既定は「進路で拠点に最も近い敵」。

### 6.2 ハードでは敵が施設も攻撃する
- easy / normal: 施設は壊れない（従来どおり。`sabotage` `ranged_disable` による一時的な弱体化・停止だけ）。
- **hard**: 施設に耐久（HP）を持たせ、敵が施設を攻撃する。
  - 施設HP: 種類ごとの基礎値 × レベル（仮: 通常の施設は敵の基礎HPの約1.5倍。城・限定施設は多め）。
  - 敵の攻撃: 進路から射程（既定1マス。`ranged_disable` を持つ敵は長め）の施設を、`attack`（ウェーブの基礎攻撃力）× 種類の倍率で攻撃する。足速型は走り抜けるので攻撃しない、装甲型は重い一撃、ボスは範囲攻撃（仮）。攻撃中は進まず足止めされる（足止めが、施設の側の「守る」対価になる）。
  - 壊れた施設: 消える。コインを半分返す（仮）。**ウェーブの合間に、不足HPに応じたコインで修理できる**。
  - 施設の側の対策: 城は周囲の施設を守る（ダメージ軽減）、聖堂（神社の枠）は周囲の施設を回復する（仮。既存の「神社」の役割を確認して合わせる）。
- 既存の `profile.enemies.action`（`sabotage` / `ranged_disable`）は、全難易度で有効（施設を壊さず、一時的に弱める）。

### 6.3 バトルの進め方の補足（戦闘の順序）
1. 敵の出現 → 2. 敵の移動・足止め → 3. 敵の攻撃（hardのみ施設へ）→ 4. 施設の攻撃 → 5. 状態異常・継続ダメージ → 6. 撃破・コイン → 7. 拠点への到達 → 8. 勝敗判定。この順序を固定し、決定的にする。

### 6.4 天候イベント
- 地域の `weatherEvent` が、そのステージで**ウェーブ中に1〜2回**（難易度で増える）、決定的な時刻（seedから）に起きる。持続は数秒〜十数秒。起きる前に予告イベントを出す（アプリが画面で知らせる）。
- 効果（仮。§10-3 で調整）:

| 種類 | 射程 | 敵の速さ | 施設の威力・攻撃速度 | その他 |
|---|---|---|---|---|
| hurricane | −1マス | −15%（押し戻す） | −10% | 飛行の敵が出現しにくい |
| tornado | ±0 | +10% | ±0 | 設置枠のうち1か所が一時使用不可 |
| blizzard | −1マス | −25% | −15% | 継続ダメージ（burn）が弱まる |
| heatwave | +1マス | ±0 | 攻撃速度 −10% | 回復（regen）の敵が強まる |
| wildfire | ±0 | ±0 | ±0 | 進路沿い数マスに継続ダメージ（敵・施設とも）。hardは施設も燃える |
| flood | ±0 | −20% | ±0 | 低い枠（農業・漁業）の威力が +15% |
| earthquake | ±0 | ±0 | ±0 | 設置枠から1つの施設が数秒停止（`ranged_disable` と同じ扱い） |
| storm | −1マス | −10% | ±0 | 漁業・港系の施設の威力 +10% |

### 6.5 季節
- ステージごとに季節を1つ持つ（**エクストラは波ごとに季節が巡る**）。地域の既定は、`profile.regions[id].season`（任意）。省略時は、天候から推定（blizzard→winter、heatwave・wildfire→summer、hurricane・storm→autumn、tornado・flood→spring、天候なし→seed で決定）。
- 季節の効果（仮）:

| 季節 | 敵 | 施設・経済 | 天候との関係 | 背景（パレットを寄せる） |
|---|---|---|---|---|
| spring | 回復（regen）の敵が強い | 農業の威力 +10% | tornado・flood が起きやすい | 明るい緑 |
| summer | 足速型がやや速い（+5%） | 漁業の威力 +10%、攻撃速度 −5% | heatwave・wildfire が起きやすい | 濃い緑・青空 |
| autumn | 通常の敵が少し硬い（+5%） | 撃破コイン +10%（収穫） | hurricane・storm が起きやすい | 黄・橙 |
| winter | 全体に遅い（−10%） | 射程 −0（見え方のみ）、炭鉱・工業の威力 +10% | blizzard が起きやすい | 白・青灰 |

- 季節と合わない天候は起きる確率を下げる（例: summer に blizzard は起きない）。確率の表は §10-3 で決める。
- 見た目: 背景の配色を季節に寄せる（アプリ側。コアは季節の id と、背景の `palette` に掛ける調整の指示だけを返す）。

### 6.6 限定施設
- 地域の `exclusiveFacility` の施設は、その地域でだけ置ける（日本と同じ考え方）。1つのステージに1種。
- 効果は種類（原型）で決める（仮。ドイツ10種・米国9種を `profile` に書いた id に対して設計する）:

| 原型 | 効果 | 該当（id） |
|---|---|---|
| 強化の核（周囲の施設を強化） | 周囲1マスの施設の威力・攻撃速度 +15% | `automotive_works`・`aerospace_works`・`tech_campus`・`national_lab` |
| 港・交通（敵を遅らせる） | 進路の近くの敵を鈍足にする | `seaport`・`container_port`・`pipeline` |
| 資源（コインを生む） | 撃破コイン +X%、または一定間隔でコイン | `stock_exchange`（DE-HE・US-NY）・`oil_derrick`・`ruhr_works` |
| 醸造・工房（継続ダメージ・範囲） | 範囲に継続ダメージ | `brewery`・`distillery`・`winery`・`porcelain_works` |
| 象徴（拠点・守り） | 拠点HPの回復、または施設を守る | `parliament`・`capitol`・`wartburg` |
| 宇宙・先端（長射程） | 長射程・貫通 | `space_center` |

- 限定施設は、置ける数・値段・効果の具体値を、自動対戦（§8）で決める。**戦争や特定の歴史を連想させる意匠にしない**（施設の見た目は `profile.facilities` の `skin`）。

### 6.7 スキル（コアに入れる）
- 既存の「ウェーブごとのスキル選択」をコアに移す。ウェーブの合間に、決定的な乱数（seed とウェーブ番号）で候補を3つ出し、1つ選ぶ。効果は**次のウェーブのみ**（複利で積み上がらない）。
- 既存の4種を初期の一覧にする: `waveAtkBonus`（施設ダメージ +25%）、`waveRangeBonus`（射程 +1マス）、`waveCoinBonus`（撃破コイン +20%）、`waveAtkSpeedBonus`（攻撃速度 +15%）。
- 追加の候補（仮）: 修理（施設を一定量回復。hard向け）、鈍足、天候の無効化（次の天候を1回防ぐ）、季節の恩恵の強化。国ごとのスキル（`profile.skills`）は将来の拡張。
- コアは `skillChoices(state)` と `chooseSkill(state, id)` を提供し、名前・説明文の文言はアプリ側。ボスのスキル（`speedBurst` / `hpRegen` / `summon` / `stunFacility`）もコアで計算する。

### 6.8 難易度（3種）
既存の `difficulty_config.dart` の値を初期値にする（easy / normal / hard）。

| | easy | normal | hard |
|---|---|---|---|
| 敵HP倍率 | 0.65 | 1.0 | 1.3 |
| ウェーブ数の加算 | −1 | 0 | +2 |
| 敵の速さ倍率 | 0.8 | 1.0 | 1.15 |
| 拠点HPの加減 | +8 | 0 | −2 |
| 撃破コイン倍率 | 1.25 | 1.0 | 0.9 |
| ウェーブ間の準備時間 | 10秒 | 6秒 | 4秒 |
| 突破時の重い減り（ボス・装甲） | なし（常に1） | あり | あり |
| 施設への敵の攻撃 | なし | なし | **あり**（§6.2） |
| 天候の回数 | 0〜1回 | 1回 | 1〜2回 |

### 6.9 エクストラステージ（クリア後）
地理パズル王の「地方決戦」（地域でまとめて戦う・7波・1.2倍）と「歴史ステージ」（全ステージをハードでクリア後に解放・8〜10波・1.4倍）にならう。

| 種別 | 解放条件（案） | 内容（案） |
|---|---|---|
| **地方決戦** | ある地方の州を一定数（例: 過半数）クリア | 地方（ドイツ=北・東・南・西、米国=北東部・南部・中西部・西部など。分け方は §10）の州の特性を混ぜる。7波、基礎HP 1.2倍、敵の構成は地方の特性、その地方の限定施設を複数置ける |
| **エクストラ** | **全州を hard でクリア**（ポストゲーム） | 国の目玉（`signature`）を前面に出す。8〜10波、基礎HP 1.4倍、**季節が波ごとに巡る**、天候イベントが増える、ボスは国の象徴的な敵（`enemySkins` を使う）。ステージは国ごとに3つ前後（段階的に強くなる） |

- ステージ名・テーマは、地形・産業・気候など**戦争や特定の歴史を連想させないもの**にする（日本の「歴史ステージ」とは別の主題。例: ドイツ=「港と工業の連合」「アルプス越え」…は仮）。
- エクストラは `Stage.kind` で区別し、生成の入力（地域の集合・波数・倍率・季節の巡り）を変えるだけで、同じ `StageGenerator`・`BattleEngine` で動く。

### 6.10 経済・勝敗
- 開始コイン・収入・施設の値段に `economy` の倍率。撃破でコイン。
- 拠点HPが0で敗北。全ウェーブを終えて勝利。

### 6.11 国の目玉（差し込み式）
`SignatureRule` の形で、`signature.id` ごとに実装を差し込む。バトルの計算は、目玉の有無を知らない。
- `federal_specialties`（ドイツ）: 州ごとの得意分野で施設を強化。隣り合う州の得意分野がそろうと追加ボーナス（隣接関係は地図から作る）。
- `weather_extremes`（米国）: 天候イベント（§6.4）と季節（§6.5）を強調する目玉。米国は地域ごとの `weatherEvent` が多く、発生回数・効果を大きくする（仮）。

## 7. API の形（案）
```dart
final stage = StageGenerator(pack, profile).generate(regionId: 'DE-BY', difficulty: Difficulty.normal);
var s = BattleEngine(stage, profile).start();
s = engine.place(s, FacilityType.factory, GridPos(3, 2));   // 置けなければ null
final r = engine.tick(s, dt);                               // (state, events)
```
`QuizEngine` と同じく、乱数は `Rng(seed)`。`dart:math` の `Random` は使わない。

## 8. テストとバランス確認
- 単体テスト: ステージ生成（§5の検証）、敵の移動、各撃ち方、各能力と行動、経済、勝敗、同じ入力で同じ結果。
- **自動対戦**（`tools/` または `test/` の重いテスト。CIには入れず手動）: ボット（例: 進路に近い枠から順に、安い施設を置く／種類を偏らせる）が、全地域×難易度を多数回（seed を変えて）遊び、勝率・敗北した波・平均の拠点HPを出す。見る点:
  1. ドイツと米国で、同じ強さの施設を置くと有利不利がどれだけ出るか
  2. 特定の地域（例: 港の州）だけ極端に簡単／難しくないか
  3. 敵の能力・行動が、実際に勝率に効いているか（効かない設定は削る）
- 数値（基礎HP、倍率、ボーナス）は仮。この結果を見て調整する。

## 9. アプリ側の責務
- ステージ・状態・イベントを描画する。`skin` id から素材（背景・施設・敵）を引く。
- 入力（施設の設置・アップグレード・撤去・スキル選択）を、エンジンの呼び出しに変える。
- 広告・課金・ランキング・実績・チュートリアル。無料の州の制限（既存の `freeRegionIds`）。

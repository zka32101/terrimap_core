# 敵キャラの再設計 v0.1（案A・C・D）

**状態: 設計のみ。コードも画像も、まだ作っていない。** バランスの数値は仮で、ボットの対戦（`BattleBot`）で確かめるまで決めない。

目的: 敵を「国ごとに違い」「数が多く」「いろいろなパターンがある」ものにする。
範囲: 案A（見た目の増量）・案C（新しい動きの敵）・案D（ミニボス）。案B（地方ごとの顔ぶれ）は今回は含めない（Aの出し分けの仕組みを使えば、あとで足せる）。

## 1. いまの仕組み（調べた結果）

- 敵の種類は4つ（`normal` / `speedy` / `armored` / `healer`）。強さの基準は `enemyBase`（`battle_model.dart`）、出る波は `kindUnlockWave`（`stage_generator.dart`: normal 1・speedy 2・healer 3・armored 4）。
- 国ごとの違いは `packs/<国>/profile.json` にある。
  - `enemies`: 種類ごとの能力・行動の割り当て。
  - `enemySkins`: 種類ごとの見た目（`skin` の id と、各言語の名前）。
  - `enemyMix`: 種類の出る割合。州ごとの偏り（`enemyBias`）もある。
- **エンジンには、すでに次の能力・行動がある**（国のデータで割り当てるだけで使える）。
  - 能力: `shield`（最初の一撃を軽減）/ `regen` / `swarm`（HPが減る代わりに数が増える）/ `flying`（進路を無視して直進）/ `disrupt`。
  - 行動: `heal_aura` / `ranged_disable`（施設を止める）/ `sabotage`（施設の威力を半分にする）。
  - ボスのスキル: `speedBurst` / `hpRegen` / `summon` / `stunFacility`。
- ボスは `isBoss`。HPは波の基礎HPの2.5倍、速さ0.6倍。エンドレスでは10・20・30波にボスが出る（見た目は同じボス）。
- 見た目の画像は、種類ごとに1枚（`assets/art/enemies/<skin>.png`）。画像がなければ図形で描く。
- リプレイは、保存した時の「ルールの版」（`BattleEngine.currentRules` = 2）で再生される。

→ **案Aは、戦闘を変えずにできる。案Cのうち、既存の能力の組み合わせで作る敵は、データだけで足せる。新しい仕組みが要る敵と、案Dは、ルールの版を上げる。**

## 2. 案A: 見た目の増量

### 方針
- 種類（4つ）ごとに、**見た目違い（バリアント）を2〜3つ**用意する。強さ・能力は同じ（見た目と名前だけ違う）。
- どのバリアントが出るかは、**敵のid・州・季節から決める**（毎回同じ結果。リプレイでも同じ見た目）。ランダム抽選はしない。
- 画像がないバリアントは、基本の絵（いまの1枚）に落ちる。

### データの形（段階1で実装したもの）
既存の `enemySkins`（種類ごとの基本の見た目）はそのままにして、**別のキー `enemyVariants`** に見た目違いを足す（旧い形を壊さない）。

```json
"enemyVariants": {
  "normal": [
    {"skin": "kobold_miner", "name": {"en": "Kobold Miner", "ja": "鉱山のコボルト"}, "when": {"groups": ["west", "south"]}},
    {"skin": "wichtel", "name": {"en": "Wichtel", "ja": "ヴィヒテル(小人)"}}
  ]
}
```
- `when`（任意）: `groups`（地方）または `regions`（州）のどちらかに当てはまれば出る。なければ、どこでも出る。**季節での出し分けは、まだ対応していない**（後の段階）。
- 見た目の候補は、基本の見た目が先頭、そのあとに、その州・地方で出る見た目違い（`CountryProfile.enemySkinIds`）。
- どれが出るかは、敵のid（`e<波>_<番号>`）から決まる（`ArtSet.enemy`）。同じ敵はいつも同じ見た目。
- 画像がない見た目違いは、基本の見た目で出る。
- 検証（`PackValidator`・`tools/validate_pack.py`）: 種類は実在、skin は空でなく重複なし（基本とも）、英語の名前あり、`when` の州・地方は実在。

### 国ごとの案（名前は仮。絵の依頼の前に確認する）
**方向性:** 民話・伝承 × 州の特色。戦争・差別・実在の宗教の聖なる存在は扱わない（`decision_log.md` のエクストラの方針と同じ）。

| 種類 | ドイツ（既存 → 追加案） | アメリカ（既存 → 追加案） |
|---|---|---|
| normal | さび妖精 → コボルト（鉱山）、ヴィヒテル（小人） | つむじ風 → ほこりの小鬼、ぬかるみの小人 |
| speedy | 疾走グレムリン → 野うさぎ（疾走）、ねずみの群れ | 回転草 → ジャッカロープ、走る木の根 |
| armored | 鉄のゴーレム → 石の巨人、氷のゴーレム | 岩のゴーレム → 化石の亀、鉄くずの牛 |
| healer | 森の精 → 水の精（ニクセ）、花の精 | サボテンの看護師 → 蜂蜜の精、雨雲の精 |

- 画像: 国ごとに追加 8〜12 枚（3バリアント × 4種類 − 既存4枚）。
- 季節で出し分ける場合（例: 冬は氷のゴーレム）は、`Stage.seasonAt(wave)` を使う。

### 実装の範囲（案A）
- core: `CountryProfile` のスキン読み込み（配列対応）、見た目を選ぶ関数（id・州・季節から決める）。画面の描画は `ArtSet` の既存の仕組みに乗せる。
- アプリ: 画像の読み込みの対応づけのみ。
- テスト: 同じ入力は同じ見た目、旧い形の読み込み、画像がないときの落ち先。

## 3. 案C: 新しい動きの敵

### C-1. 既存の能力の組み合わせで作る敵（データだけ。ルールの版は変えない）
今の4種類の枠（`kind`）は変えずに、**バリアントごとに能力・行動を持たせる**案と、**新しい種類の枠を足す**案がある。後者は `enemyBase` に行が増えるので、C-2に含める。

### C-2. 新しい種類の枠（ルールの版を 3 に上げる）
| 種類（仮） | 動き | 使う仕組み | 狙い |
|---|---|---|---|
| 飛ぶ敵（flyer） | 進路を無視して拠点へ直進 | `flying`（既存） | 進路沿いの配置が効かない。射程の広い施設が活きる |
| 妨害の敵（saboteur） | 近くの施設の威力を半分にする | `sabotage`（既存） | 後方の施設を守る戦略 |
| 群れの敵（swarm） | HPが低く、数が多い | `swarm`（既存） | 範囲攻撃（splash）が活きる |
| 分裂の敵（splitter） | 倒すと小さい敵が2体出る | **新しい仕組み** | 火力の分散を考える |

- **新しい仕組みが要るのは分裂だけ。** ほかは既存の能力で足せる。
- 出る波は、`kindUnlockWave` に足す（例: flyer 5波・saboteur 6波・splitter 7波）。
- バランスは、`BattleBot`（casual / regular / expert）と全地方・全難易度の対戦テストで確かめる。勝率の目安は既存のテスト（`regional_test`）に合わせる。
- 国の味付け: ドイツ = 飛ぶ敵「ヴォルペルティンガー（羽の生えたうさぎ）」、アメリカ = 飛ぶ敵「ほこりのカラスの群れ」など（仮）。

### ルールの版（リプレイ互換）
- 新しい種類・仕組みは `rules >= 3` のときだけ有効にする。**古いリプレイは版2のまま再生**されるので壊れない。
- 招待コード・週替わり・今日の挑戦は、最新の版で作る（既存の方針と同じ）。

### 段階3で実装したもの
- 種類: `flyer`（`flying`）・`saboteur`（`sabotage`）・`swarmer`（`swarm`）・`splitter`（新規）。ルール版を 3 に上げた（`BattleEngine.currentRules`）。
- 出る波（`kindUnlockWave`）: flyer 5・swarmer 5・saboteur 6・splitter 7。
- 出現の重みは、プロファイルの新キー `enemyMixV3`（`enemyMix` に足し合わせる）。**`enemyMix` は旧4種のまま**にし、`StageGenerator(rules:)` が 2 以下なら `enemyMixV3` を使わない。古い記録のステージは同じに作られる。
- 分裂: 倒すと2体（`splitCount`）に分かれる。子は元の最大HPの35%（`splitHp`）。子は分かれない（id に `_p`）。波は子を倒すまで終わらない。
- 国の見た目と名前（仮）: DE = ヴォルペルティンガー・坑道のいたずら小鬼・こうもりの群れ・泥のかたまり／US = ほこりのカラス・大草原のいたずら者・イナゴの群れ・タールのかたまり。画像は未作成（図形で描く）。
- バランス: 既存の全地方×難易度のボット対戦テストが、そのまま通る。細かい数値は実機での確認が要る。

### 見た目違いごとの特性（段階3の追加）
- `enemyVariants` の各要素に、任意の `trait` を書ける。`hp`・`speed`・`baseDamage` は種類の国の特性に掛ける倍率、`armor` は足す値、`ability`・`action` は 'none' 以外を書くと、その種類の能力・行動の代わりになる。範囲は `enemies` と同じ（検証も同じ）。
- 効くのはルール版3から。どの見た目が出るかは `CountryProfile.variantFor`（`enemySkinIds` の並びから敵のidで決める）で、画面の見た目（`ArtSet.enemy`）と同じ選び方なので、見えている敵と効く特性が一致する。ボスには付かない。
- DE・US の16の見た目違いに、特性を割り当てた（仮）。例: 石の巨人 = HP高く遅い／氷のゴーレム = 再生／ねずみの群れ = 群れ／蜂蜜の精 = 回復の輪。

### 新しい敵の国ごとの差（段階3の追加）
- ドイツ（堅実）: 飛ぶ敵は硬く遅い／妨害は威力を半分にする（sabotage）／分裂は硬く重い。分裂が多め（0.12）。
- アメリカ（足が速い）: 飛ぶ敵は脆いが速い／妨害は施設を止める（ranged_disable）／群れは速く被害が大きい。飛ぶ敵・群れが多め（0.12・0.14）。
- 数値は仮。テストは、4種類すべてが国で違うこと（倍率・能力・出る割合）を確かめる。

## 4. 案D: ミニボス

### 方針
- **地方ごとに1体**（`profile.groups`。ドイツ・アメリカとも4地方 = 4体）。通常の州ステージには出さず、**地方決戦・エクストラ・エンドレス（10・20波）**に出す。
- 既存のボス（`isBoss` + `bossSkill`）の仕組みを使い、**HPを軽く（通常ボスの0.5〜0.6倍）、スキルを1つ**にする。
- スキルは4つ（`speedBurst` / `hpRegen` / `summon` / `stunFacility`）から、地方の特色で選ぶ。

### 案（仮）
| 地方 | ミニボス（仮） | スキル |
|---|---|---|
| ドイツ 北 | 霧の海の番人 | `stunFacility` |
| ドイツ 南 | 山の岩の守り手 | `hpRegen` |
| アメリカ 西 | 砂嵐の主 | `speedBurst` |
| アメリカ 北東 | 紅葉の大木 | `summon` |

- エンドレス: いまは10・20・30波とも同じボス。**10波=ミニボス、20波=別のミニボス、30波=ボス**にして、波ごとに見た目と名前を変える。
- 画像: 地方の数だけ追加（ボスの規格 512×512 透過PNG）。

### 段階4で実装したもの（ルール版4）
- **hard だけの敵:** `brute`（硬く重い・盾）と `jammer`（近くの施設の射程を縮める）。出現の重みは新キー `enemyMixHard`（hard かつ版4のときだけ `enemyMix` に足す）。出る波は brute 4・jammer 6。easy・normal・版3以前には出ない。
- **ミニボス:** 新キー `miniBosses`（地方id→見た目・名前・スキル）。`StageWave.miniBoss` が立った波の最後の1体がミニボス（`Enemy.isMini`）。HPは基礎HPの1.4倍（ボスは2.5倍）、速さ0.75倍、スキルを1つ、拠点への被害は重い設定で2。報酬・スコアはボスの半分程度。
  - 地方決戦・エクストラ: 中盤の1波（`(波数+1)÷2`）。通常の州ステージには出ない。
  - エンドレス: 10・20波がミニボス、30波だけがボス（版3以前は10・20・30波ともボス）。
  - 見た目: 画像は `bosses/<skin>`（`ArtSet.miniBossId`、アプリが `miniBossFor` で選ぶ）。なければ橙の縁の図形。登場時は「MINI BOSS」の表示。
- DE（仮）: 北=霧の海の番人（stunFacility）／南=山の岩の守り手（hpRegen）／西=黒い森の狩人（summon）／東=湖の水の主（speedBurst）。US（仮）: 西=砂嵐の主（speedBurst）／北東=紅葉の大木（summon）／中西部=大草原の風の王（hpRegen）／南=沼地の大ワニ（stunFacility）。
- 古い記録: 版3以前のステージは `StageGenerator(rules:)` で同じに作られ、ミニボス・hard専用の敵は出ない。

| 2 | 案C-1: 既存の能力で作るバリアント（データのみ） | 変えない | あると良い |

## 6. 受け入れ条件（各段階共通）
- `flutter analyze` クリーン、全テスト通過。
- 古いリプレイが、版2のまま同じ結果で再生される。
- 全地方・全難易度のボット対戦で、止まらず終わる。勝率の目安が既存の範囲から大きく外れない。
- 画像がなくても、図形で描いて動く。
- 文言は全言語にある（機械翻訳は、その旨を記録する）。

## 7. 決めてほしいこと
1. 見た目の方向性: 民話・伝承 / 自然・産業 / 州の特色（組み合わせ可）。
2. 新しい敵の数: C-2 の4種類のうち、どれを入れるか（分裂は仕組みの追加が要るので、最後でもよい）。
3. ミニボスの数と出す場所（地方決戦のみ / エンドレスにも）。
4. 画像の作成: 別セッションで作る前提で、依頼書を用意するか。

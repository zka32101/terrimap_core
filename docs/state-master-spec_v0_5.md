# State Master（仮）— 州・地方クイズ テンプレート仕様 v0.1

作成日: 2026-10-17 / 目的: 「国データ差し替え型」で量産できるか、2本で需要検証する

## 0. 基本方針（v0.3追記）: 共通エンジン＋国別アプリ
- コードは**共通エンジン**（クイズ・地図タップ・進捗・デイリー・課金/広告）1本で管理
- 公開は**国ごとに別アプリ**（例: ドイツ版・米国版）。国別のASO・価格ティア・スクショ・レビューを最適化するため
- 国ごとの差分は `country_pack`（データ・画像・文言）とストア資料のみ
- 「世界まとめ版」は、国別アプリで当たってから判断（現時点では作らない）
- 当面は**2本（ドイツ版・米国版）のみ**で、エンジンの再利用性とストア運用の手間を確かめる
- 既存の共通基盤（app_common_kit など）の流用範囲は要確認

### 0-2. 共通基盤の方針（v0.4追記、v0.5で既存コード調査を反映。調査結果は0-3）
既存の都道府県系（小学コレ！社会、地理パズル王）と、今回の州クイズを組み合わせて、**地域データ型の共通エンジン（region_engine。パッケージ名は仮称 `region_core`）**を作る。

| 層 | 内容 | 状態 |
|---|---|---|
| 1. 基盤 | 課金・広告・認証・通知（yourwish_core / yourwish_ui / app_common_kit） | 既存 |
| 2. region_engine | 地図表示・タップ、出題（位置・首都・旗など）、進捗（塗りつぶし）、デイリー、ストリーク、共有カード、country_pack 読み込み | 新規（既存コードから抽出） |
| 3. country_pack | 国ごとのデータ（JP 47県、DE 16州、US 51…）。名称（多言語）・首都・旗・地図・**産業/特産** | 新規 |
| 4. アプリ | 小学コレ！社会（JP・学習）／地理パズル王（TD・産業データで敵を生成）／州クイズ ドイツ版・米国版 | 一部既存 |

- country_pack のスキーマは、3系統のアプリが使う項目（地図・名称・首都・旗・産業/特産・学習要点）を**最初から含める**。これが「組み合わせ」の中核
- TDのゲームロジックは共通化せず、地理パズル王側のモジュールとして region_engine の上に載せる

**進め方（順序）**
1. 既存リポジトリの棚卸し（地図の描画方式、進捗・デイリー・課金の実装、再利用できる範囲）
2. country_pack のスキーマを確定（3系統の要件を満たす最小項目）
3. 新規アプリ（州クイズ ドイツ版）を region_engine 上に作り、エンジンを抽出・検証
4. 米国版で再利用性を確認
5. 既存アプリ（小学コレ！社会・地理パズル王）の移行は**後回し**。公開済み・開発中の本体を先に作り替えない

**リスク**
- 既存アプリの改修を先にすると、新規検証が遅れる
- エンジンを汎用にしすぎると、最初の1本が出ない（ドイツ版の要件に絞って抽出する）
- 日本の学習指導要領に依存したデータ構造を、そのまま国共通にできない（学習要点は任意項目にする）

### 0-3. 既存コード調査結果（v0.5追記、2026-10-17。構造・ファイル見出しの確認のみ。ビルド・実行は未確認）
**対象リポジトリ**
| リポジトリ | 規模・構成 | 備考 |
|---|---|---|
| zka32101/geography_puzzle_king（モノレポ `apps/geography_puzzle_king`） | 約3.5万行。Flutter / Riverpod / Firebase / google_mobile_ads | 7画面のUIは完成（ステータス文書は2026-06-14で更新停止。現在の実装状況は不明） |
| zka32101/social_quiz_app（社会コレと判断。要確認） | 約5.2万行。Flutter / Riverpod / Hive / RevenueCat / go_router / flutter_map | `features/world_map`（世界地図クイズ）、`features/prefecture` あり |
| zka32101/app_common_kit | 全アプリ共通（設定画面、広告、課金権利、同意、保護者ゲート、進捗など） | 層1（基盤）に相当 |
| zka32101/shared_core | 小学コレシリーズ専用（ゲーミフィケーション、Firebase） | 小学コレ系の共通部品 |
| 各シリーズの `*_core`（shoukore_core_global, ukalab_core, japanaut_core ほか） | シリーズ別の共通パッケージ | `region_core` はこの型に合わせる |

**わかったこと**
1. **重複がすでに発生**: 地理パズル王の境界データ（約1,130行）は、社会コレのデータの移植。出典も同じ（国土地理院「地球地図日本」の非公式ミラー）
2. **地図の描画方式が2系統**: 地理パズル王は自前描画（`CustomPainter`、依存なし）。社会コレは `flutter_map`＋`latlong2`（タイル使用の有無は未確認）
3. **出題データが日本語直書きのConstマップ**（`prefectureQuizData` など）。文言は `tr()` で翻訳する日本語キー方式。国別展開にはID＋JSONのデータ駆動が必要
4. **社会コレの世界地図クイズ**は中身未精査。海外の国別クイズの土台になる可能性

**方針の修正**
- 地図は**自前描画（依存なし・オフライン）に統一**する案を第一候補にする（タイル不使用なら）。社会コレの `flutter_map` 版は、タイル使用の有無を確認してから判断
- 出題・地域データは **IDベースのJSON（country_pack）** に変更
- `region_core` の最初の切り出し元は地理パズル王の地図ウィジェットと境界モデル。既存アプリ（社会コレ・地理パズル王）には手を入れない

**リスク**
- **境界データのライセンス**: 営利利用は出典表示に加え、国土地理院への利用報告が必要。2ファイルで「対応済み/対応予定」と「別途対応要」の記載が食い違う。日本版の公開前に実際の対応状況を確認
- 海外の州境界データは別の出典・ライセンスの確認が必要（候補は各国の公的機関の公開データ、Natural Earth など。**未調査・要確認**）
- 地理パズル王の現在の状態（リリース済みか、設計止まりか）が不明

**次の一手**
1. `region_core` の最小仕様（地図描画・country_pack読み込み・出題・進捗）を確定
2. 地理パズル王の地図部分を切り出す試作（既存アプリは触らない）
3. 海外（ドイツ・米国）の境界データの出典とライセンスを調査

## 2. 差別化（批判的レビュー）
- 既存の州クイズは「地図・旗・首都の4択」止まりで、機能差は小さい。差別化は**弱い**
- 差別化候補（優先順）:
  1. 地図タップ＋「形当て」＋特産・名所写真の複合出題（既存は単機能が多い）
  2. 連続日数・コレクション（称号・バッジ）で習慣化
  3. 「全州制覇」進捗の共有カード（SNS共有）
- 判断: 差別化が弱いため、**小さく出して実データで判断**（本格投資はしない）

## 3. MVP（Must 5個）
1. 地図タップ（州の位置当て）
2. 4択クイズ（首都・旗・紋章／名称）
3. 形当て（シルエット）
4. 進捗・称号（州ごとの習熟度、連続日数）

6. デイリーチャレンジ＋絵文字グリッド共有（Wordle型）※v0.2で追加。拡散の主軸（Must 6個目。MVP規律の上限5個を超えるため、4「進捗・称号」を地図塗りに統合して実質5個に圧縮する）

## 4. 国データ差し替え設計
```
country_pack/
  meta.json        # 国名, 言語, 区分名(州/県), 件数
  regions.json     # id, 名称(多言語), 首都, 旗, 紋章, 面積, 人口
  geo.json         # 地図ポリゴン（GeoJSON）
  media/           # 旗・紋章・シルエット画像
  strings/<lang>.json
```
- アプリ本体は共通エンジン。国別アプリは、ビルド時に `country_pack` を差し替えて生成する（国ごとに別バンドルID・別ストア登録）
- 新国版は `country_pack` の差し替えと、ストア文言・スクショのみ
- 国別アプリが増えるほどストア更新・審査・サポートが増えるため、運用手順（ビルド・申請のスクリプト化）を最初に整える
- 既存資産（app_common_kit）のクイズ・課金・進捗モジュールを流用する前提（流用可否は要確認）

## 5. 収益設計（仮説）
- 無料: 最初の一部の州（例: 4〜5州）＋広告（バナー／終了時インタースティシャル）
- 課金: ①全州解放（買い切り）②広告削除 ③（将来）複数国パック
- 価格: 国別ティアで設定。初期値は競合の価格帯を確認してから決める（未調査）
- サブスクは、コンテンツ追加の頻度が低いので**MVPでは入れない**

## 6. ストア・法務チェック
- ドイツ: Impressum相当・プライバシーポリシー（GDPR）、ATT・同意管理（広告SDK）
- 米国: COPPA（子どもが使う想定なので年齢区分と広告設定に注意）
- 旗・紋章・地図データの**ライセンス確認**（パブリックドメイン／CC表記の要否）
- ASO: 国別キーワード、スクショはその国の言語で作成

## 7. 検証計画（2〜4週間）
- 指標: インストール、D1/D7継続率、課金率、広告ARPDAU、CPI（広告出稿する場合）
- Go/No-Go（**仮の目安。実データで見直す**）:
  - D1継続率が低すぎる、または課金率がほぼゼロ → 縮小・停止
  - どちらか1国で手応え → 同国の別ジャンル（首都・歴史）と近隣国へ展開
- 広告出稿は少額で、自然流入との比較を見る

## 8. リスク
- 需要が小さい（ドイツ版の競合評価数が少ない＝需要の少なさの可能性）
- 教育用途は子ども向け扱いになり、広告・課金の規制が厳しい
- 地図データの精度・ライセンス
- 多言語・多国展開時の運用コスト（ストア更新・審査・サポート）

## 9. 次のアクション

2. app_common_kit の流用範囲を確認
3. ドイツ版の最小実装 → 米国版は同じコードでデータ差し替え

## 10. 差別化・面白さ要素（v0.2追加・すべて仮説／未検証）

### フェーズ1（MVPに入れる）
| 要素 | 内容 | 狙い |
|---|---|---|
| デイリーチャレンジ | 全員同じ問題を1日1回。結果を🟩🟥の絵文字グリッドでSNS共有 | 広告費ゼロの拡散、毎日起動の習慣化 |
| 地図が塗られていく | 正解した州が塗られ、全州で完成。進捗・称号と統合 | 進捗の可視化、コンプ欲 |

### フェーズ2（初期データで手応えがあれば追加）
| 要素 | 内容 | 狙い |
|---|---|---|
| サバイバルモード | 間違えるとライフ減、限界まで続ける | 1回あたりの熱量、ハイスコア更新 |
| ヒント消費制 | 広告視聴またはコインでヒント | 広告・課金の接点 |
| 友達とタイム勝負 | 同じ問題を非同期で競う（リアルタイム対戦は後回し） | 招待による拡散 |
| 距離当て | 「ここから◯◯州の中心まで何km?」 | 感覚を鍛える遊び方の追加 |

### フェーズ3（コンテンツ追加・運用負荷が増える）
| 要素 | 内容 | 注意 |
|---|---|---|
| 地域別ランキング | 州ごとの平均正答率など、ご当地プライドを刺激 | ユーザー数が少ないと成立しない |
| 雑学クイズ | 特産・方言・名物料理・出身有名人 | 事実確認の手間、出典の管理 |
| 写真当て | 「この写真はどの州?」 | 写真素材のライセンス確認が必須 |
| ご当地あるある | その国の人が笑えるネタで出題 | 固定観念・偏見ネタは炎上リスク。基本は見送り、導入するなら現地ネイティブのレビュー必須 |
| 学校・親子モード | 先生が出題範囲を選び、クラスで結果共有 | 子ども向け規制（COPPA/GDPR-K）の確認が前提 |

### 導入判断のルール
- フェーズ1のみでMVPを出し、D1/D7継続率・共有率を見てからフェーズ2へ
- 共有率が低ければ、拡散前提の要素（友達対戦・ランキング）への投資は止める
- 効果の大きさは現時点では推測。実データで優先順位を入れ替える
